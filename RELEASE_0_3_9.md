# CAEL 0.3.9 — conversation and checked follow-ups

Authorized release, 2026-11-07. CAEL retains its non-neural symbolic/count/automaton
architecture. This package promotes the frozen conversation R3 candidate, with
declared version/portable-policy integration changes. No benchmark values or
failed transfer cases were used to patch the frozen research source.

The source freeze is
`6b66428369ec45953472820e6039f7f7137e5e856b2874eda2ab6651e853119f`.
Runtime version is 0.3.9; the checksum-identical public resource bundle remains
0.3.7 (`8efd22d7fa670e7f011d262c33a7e026941f279e71ee2014614d5d4cf5ecf79b`).
Protected choice/word-math solvers, inherited resource weights and CA kernels
are unchanged. Symbolic dialogue/event/state tables are included with source.

Added capability includes visible-request rechecks, complete literal positional
and keyword-example checking, exact guarded option comparisons, attributed user
facts and bounded source-linked definition composition. Earlier 0.3.8 personal
fact, listening, coding-condition and mobile-worker fixes are retained.

The qualified bounded Python-help adapter is now part of the public package and
installed once by Assistant construction, including the worker entry point.
The VM itself is not extended. This is integration of the tested policy, not a
claim of whole-runtime security certification. Source and dependency hashes,
portable regression checks and deployment evidence are recorded separately.

Latest authored fresh transfer: useful answers 10/29 -> 22/29, and complete
positive-task conversations 2/14 -> 9/14, versus the previous development
candidate. Boundaries include refusal/clarification, not solved positive tasks.
All failures and interpretation sensitivities remain in the bundled evidence.
There is no new Qwen win or standard benchmark claim.

Known gaps include stale option switches, some dictionary follow-ups, generated
practical examples, compound source checks and incomplete lexical retrieval.
Read README.md and benchmarks/conversation_039_r3/REPORT.md for scope.

Public assets contain no private conversations/photos, credentials, image/portrait
weights or local session configuration. Existing publications are not overwritten.
The Vynly deployment preserves the existing tunnel and session settings, with
the prior worker/source retained for rollback; live verification is recorded
only after deployment succeeds.
